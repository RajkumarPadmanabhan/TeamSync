ACCESS CONTROL

Two roles, two very different dashboards

Permissions are enforced at the API layer — every endpoint checks role before it checks intent.

A

Admin

  • Create and manage projects
  • Add team members
  • Create and assign tasks
  • Set priorities and deadlines
  • View project progress across the team
M

Team Member

  • View assigned tasks
  • Update task status
  • Add comments and progress updates
  • View deadlines and priorities
  • Accept or reject project invitations

API SURFACE

Endpoint reference

Base URL http://localhost:8000/api/ — full request and response schemas are in the API documentation PDF below.

MethodPathPermissionDescription
POST/api/auth/login/AllowAnyAuthenticate and issue a JWT
POST/api/auth/register/AllowAnyRegister a new member or admin
GET/PATCH/api/auth/me/AuthenticatedFetch or update the current profile
GET/api/projects/AuthenticatedList active projects and stats
POST/api/projects/Admin OnlyCreate a project and assign members
PATCH/DEL/api/projects/{id}/Admin OnlyUpdate or delete a project
POST/api/projects/invitations/send_request/Admin OnlySend a join request to a member
POST/api/projects/invitations/{id}/respond/Member OnlyAccept or reject an invitation
GET/POST/api/tasks/AuthenticatedList, filter, or assign a task
PATCH/api/tasks/{id}/AuthenticatedUpdate status or deadline, log audit entry
GET/api/tasks/{id}/history/AuthenticatedFetch deadline revision history
GET/POST/api/tasks/{id}/comments/AuthenticatedRead or post task comments
DATA MODEL

Seven normalized tables

Foreign keys, cascading deletes, unique constraints, and timestamp auto-recording throughout. Full ER diagram in the download below.

User
Credentials, role (ADMIN/MEMBER), department
Project
Scope, dates, status, creator, assigned members
ProjectInvitation
Join requests — pending, accepted, rejected
Task
Title, priority, status, deadline, assignee
DeadlineHistory
Audit log — previous vs. new deadline, reason, editor
Comment
Discussion threads and status progress notes
